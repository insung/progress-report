# Issue #1 검토 기준

구현 전 고정 입력. 구현 세션 열람 금지.

## 사용 방법

handoff·task를 AC와 대조하고 정적 검사를 직접 재실행한다. review-input-report-boundaries.md의 입력 절만 새 실행자 3명에게 전달한다. 아래 기대 결과는 전달하지 않는다.

## AC별 기준

| AC | 기계 확인 | 판단 질문 | 실패 예 |
| --- | --- | --- | --- |
| AC-01 | 요약 헤더 대조 | 목표가 결과인가 | 진척 컬럼 유지 |
| AC-02 | 출력 순서·명칭 대조 | 조건부 구역이 필요한 때만 나오는가 | 다음 한 걸음 사용 |
| AC-03 | worktree 표 헤더 대조 | 관련 작업 위치·용도가 맞는가 | 무관한 등록 워크트리 포함 |
| AC-04 | git worktree list --porcelain 명시 | 조회 실패와 부재를 구분하는가 | 기본 checkout을 별도 작업 워크트리로 표시 |
| AC-05 | 작업 위치 조건 대조 | 작업별 위치 대응이 분명한가 | 항상 불필요한 작업 위치 열 추가 |
| AC-06 | 검증 방법·상태 사례 대조 | 명령 존재와 실행 통과를 구분하는가 | lint만 통과한 작업 완료 판정 |
| AC-07 | quick_validate.py, 템플릿 상대 링크 존재 | 규칙 정본과 구조가 분리됐는가 | 템플릿과 SKILL 규칙 충돌 |
| AC-08 | README 두 언어·새 실행자 3회 | 경계에서도 출력 계약을 지키는가 | 설명만 고치고 예시 구형 유지 |

## 우회 확인

- baseline과 GREEN 입력 동일성·실행자 분리·출력 전문 보존
- 미실행 검증·사용자 승인 대기를 완료로 표시하지 않음
- 기존 목표 요약 변경 보존, 기본 checkout patch 해시 비교
- 시나리오 가상 경로·명령을 실제 프로젝트 증거로 오인하지 않음

## 공통 확인

- 기존 상태 값 7종·증거 기준·범위 규칙 유지
- 템플릿 placeholder·주석이 실제 보고에 출력되지 않음
- 매니페스트 버전 변경·설치·원격 push·PR·merge 없음
- 문서 정본 링크 및 task·handoff 결과 추적 가능
